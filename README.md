# USB 两轴摇杆实时监视

无依赖的单文件网页，使用浏览器 Gamepad API 显示两轴实时值与二维位置。支持设备选择、轴选择和反向。所有读取在本地完成，不向服务器上传数据。

## 启动

在此目录执行：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

使用桌面浏览器打开 <http://localhost:8000>。插入 USB 摇杆，点击网页后拨动摇杆；如有按钮，也可以按一下。保持页面在前台。默认使用轴 0 和轴 1，可按实际设备调整来源和方向。

## 数据与兼容性

- 原始 X 行程为 -0.7752 至 +0.9081，原始 Y 行程为 -0.9062 至 +0.8025。原始向量半径 `r = hypot(x, y)` 小于或等于 0.002 时输出零，这是圆形死区。
- 每个象限使用该方向的 X/Y 行程上限 a、b 校准，`u=x/a, v=y/b, q=hypot(u,v)`。校准椭圆沿原始输入方向的边界半径为 `R=r/q`；将半径区间 `[0.002, R]` 线性映射为 `[0, 1]`：`t=clamp((r-0.002)/(R-0.002), 0, 1)`，输出向量 `(u/q, v/q) × t`。这样保留非对称行程校准，并将输出限制在单位圆内。
- 超出圆周的向量沿同一方向截断到圆周，两个分量同步缩放。例如校准后的 (100%, 100%) 输出为 (70.7%, 70.7%)。百分比保留一位小数；精确位置和进度条使用未舍入值。
- 归一化后向左旋转 90°。由于页面坐标 Y 向下，显示 X = 原始 Y，显示 Y = -原始 X。例如原始 X 推至正最大值，位置点移至顶部；原始 Y 推至正最大值，位置点移至右侧。数值、进度条和位置图使用同一结果。
- 来源选择对应旋转前的原始轴；反向选项作用于旋转后的显示轴。校准范围和死区在 index.html 的 `calibration` 和 `deadzone` 常量中设置。读数不是电压或 ADC 原始数据。
- 设备须被操作系统和浏览器识别为游戏控制器。USB 接线图片无法确定设备协议。
- 自定义 HID、串口或私有 USB 协议需要厂家文档进一步适配。
- 无数据时先保持页面可见并操作摇杆，再检查系统是否识别为游戏控制器。支持情况也取决于操作系统、设备驱动及浏览器。
- 在独立浏览器标签页使用 localhost 或 HTTPS；嵌入预览可能被浏览器权限策略阻止。

## 检查

安装 Node.js 后执行：

```sh
node test.mjs
```

测试在最小浏览器环境模拟中运行真实页面脚本，检查连接、轴数据、位置、轴选择与方向、设备选择、轴不足、断开及访问错误，以及正负行程、圆形死区、斜向径向线性映射、圆周截断、全象限圆内约束和左旋 90°。它不替代真实 USB 设备验证。

API 参考：[MDN Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API)。
